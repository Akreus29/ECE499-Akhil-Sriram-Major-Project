# ICD — Shakti Yamuna ↔ KCF/NCC Full-Frame Tracker IP

**Interface Control Document, v3.1 (LOCKED)**
Contract between the Shakti Yamuna SoC (`gc2025`) and the Image-Processing IP
wrapper (`image_ip_axilite`).

**v3.1 additions (backward-compatible with v3.0):**
- **Preloaded target designation.** The designation frame + target centre are
  baked into the IP at build time (`data/target_frame.mem`, generated by
  `scripts/gen_target_mem.py`). The IP **self-runs the designation sequence at
  boot** (parameter `AUTO_TINIT=1`), so runtime needs no designation upload —
  NCC acquires from the very first camera frame. Software just polls
  STATUS.done once after reset before streaming frames.
- **Packed RESULT register (0x38)** — one AXI read returns the whole tracker
  state (found, tracking, algo, absolute row+col). Understandable identically
  for NCC and KCF: both report the **absolute** target centre.
- **STATUS[5] = found** — uniform "target located this frame" bit for NCC and KCF.
- **NCC search stride** (parameter, default 2) — quarters acquisition time to
  ~4 ms with ≤ 4 px coarse error (the KCF crop refines it anyway).
- **Shared FFT engine** — the forward FFT and IFFT (which never overlap in
  time) now share one `fft2d_64`, roughly halving the IP's LUT/FF footprint.
  Functionally bit-identical; no interface change.

**v3.0 (still in force):** 320×240 RGB565 camera format, 2 px/write, hardware
grayscale + un-flip, `KCF_THRESH` (0x34) loss threshold, rescaled KCF
confidence (≈ 200–300 locked).

Any change to this document is a version bump and must be agreed by both sides.

## 1. Scope & physical interface

Single **AXI4-Lite slave** (32-bit data/address) plus clock/reset.
No AXI-Stream, no DMA, no interrupt wiring in v3.

| Item | Value |
|---|---|
| SoC attachment | Slave 5 on the Yamuna slow fabric (`Kcf_slave_num`) |
| Base address | **`0x0004_2000`** (window `0x0004_2000–0x0004_20FF`) |
| Clock | SoC `core_clk` = **50 MHz** (single domain, no CDC) |
| Reset | `rst_n = ~soc_reset`, async active-low |
| AXI4-Lite style | Single outstanding transaction; AW/W in either order; BVALID held until BREADY; RVALID held until RREADY |

⚠️ Address decode is `addr[5:2]` — 16 word slots (0x00–0x3C); offsets ≥ 0x40
alias onto 0x00. Software must never access ≥ 0x40.

**RTL contract files:** SoC→IP direction = `src/frame_input_if.sv`;
IP→SoC direction = `src/result_output_if.sv`. The top is wiring only.

## 2. Register map

| Offset | Name | Access | Bits | Description |
|--------|------|--------|------|-------------|
| 0x00 | CTRL | W (self-clearing) | [0] start · [1] soft_reset · [2] target_init | Latched pending; fire when frame complete (`BUF_IDX == 76800`) |
| 0x04 | MODE | R/W | [1:0] | 0 = AUTO (NCC acquire → KCF track → loss fallback) · 1 = NCC only · 2 = KCF only |
| 0x08 | THRESH | R/W | [15:0] | Q8.8 signed (reset 0x0080 = 0.5). **Acquisition**: NCC² score ≥ THRESH → switch to KCF |
| 0x0C | LAMBDA | R/W | [15:0] | KCF regularisation λ, Q8.8 signed (reset 0x0001) |
| 0x10 | STATUS | R | [0] busy · [1] done · [3:2] algo (0=NCC, 1=KCF) · [4] tracking · **[5] found** | `done` latches; cleared by next start / soft_reset. **found** = target located this frame (NCC² ≥ THRESH, or a valid KCF lock) |
| 0x14 | ABS_ROW | R | [8:0] | **Absolute upright** target-centre row, 0–239 (same meaning for NCC and KCF) |
| 0x18 | ABS_COL | R | [8:0] | Absolute upright target-centre col, 0–319 (same meaning for NCC and KCF) |
| 0x1C | CONFIDENCE | R | [15:0] | Q8.8 signed. NCC² score (0…256=1.0) in acquisition; KCF peak (typ. 200–300 locked) in track |
| 0x20 | IRQ_MASK | R/W | [0] | **Reserved** — write 0 (poll mode) |
| 0x24 | IRQ_STAT | R/W1C | [0] | **Reserved** |
| 0x28 | IMAGE_FRAME | W | [31:0] | **2 RGB565 pixels** per write (§3); reads 0 |
| 0x2C | TARGET_POS | R/W | [8:0] row · [24:16] col | Designation centre (upright coords); clamped to row [32, 208], col [32, 288]. **Resets to the baked target centre** (v3.1 preload) |
| 0x30 | BUF_IDX | R/W | [16:0] | Pixel index 0–76,800. Write **0** before each frame (also resets the decimator/scan position). Only 0 and 76,800 supported for writes |
| 0x34 | KCF_THRESH | R/W | [15:0] | Q8.8 signed (reset 0). **Loss**: KCF peak < KCF_THRESH for 3 consecutive frames → fall back to NCC. **0 disables fallback.** Typical useful value ≈ 0x0080 (half the locked confidence) |
| 0x38 | **RESULT** | R | [31] found · [30] tracking · [29:28] algo · [24:16] abs_row · [8:0] abs_col | **v3.1 — one read gives the full result** for either algorithm. Packs the same values as STATUS+ABS_ROW+ABS_COL |
| 0x3C | — | — | — | Reserved: read 0, writes ACKed and ignored |

### Reading the result (both NCC and KCF)

Both algorithms report the **absolute** target centre in ABS_ROW/ABS_COL (KCF
converts its internal displacement to an absolute coordinate before reporting
— software never sees a raw displacement). The single-read `RESULT` (0x38)
gives everything at once:

```c
uint32_t r = REG(0x38);
int found    = (r >> 31) & 1;        // target located this frame
int tracking = (r >> 30) & 1;        // 1 = KCF lock active
int algo     = (r >> 28) & 3;        // 0 = NCC, 1 = KCF
int row      = (r >> 16) & 0x1FF;    // 0..239, absolute
int col      =  r        & 0x1FF;    // 0..319, absolute
```

## 3. Frame-upload protocol (IMAGE_FRAME)

1. Camera byte stream per frame: 153,600 bytes = 76,800 RGB565 pixels,
   **high byte first**, scan order **bottom-right → top-left** (right-to-left
   within each row, rows bottom-to-top) due to the sensor flip+mirror.
2. Software packs 4 consecutive stream bytes into each 32-bit write exactly
   as they land in a little-endian word (i.e. `((uint32_t*)buf)[j]`):
   - `pixel_a = {wdata[7:0], wdata[15:8]}` — first-arriving pixel {H,L}
   - `pixel_b = {wdata[23:16], wdata[31:24]}` — second pixel
3. 38,400 writes per frame; BUF_IDX += 2 per accepted write; complete at
   **76,800** (arms pending start / target_init).
4. Hardware converts each pixel to 8-bit grayscale
   (BT.601: `(77·R8 + 150·G8 + 29·B8) >> 8`, components MSB-replicated to
   8 bits) and stores it at the **un-flipped upright position**. All
   coordinates in this ICD are upright: row 0 = top, col 0 = left.
5. Software writes `BUF_IDX = 0` before every frame. Writes while
   `STATUS.busy = 1` or past 76,800 are ACKed OKAY and discarded.
   Abort/resync: write `BUF_IDX = 0` and restart the frame.
6. The IP builds a 4×-decimated 80×60 copy on the fly (used by NCC) — no
   software involvement.

## 4. Target designation & tracking model

**Designation — PRELOADED (v3.1 default).** The designation frame and target
centre are baked into the IP bitstream (`data/target_frame.mem` + the
`TGT_ROW`/`TGT_COL` parameters, produced by `scripts/gen_target_mem.py` from
the demo target photo). With `AUTO_TINIT=1` the IP runs the whole designation
sequence **automatically at boot** — crop 64×64 at the baked centre, build the
NCC template, pre-train KCF — and raises STATUS.done when ready. Software just
waits for that once after reset, then goes straight to the tracking loop; no
designation upload is needed. `TARGET_POS` reads back the baked centre.

**Designation — runtime (optional / re-designation).** The register path still
works: upload a frame → write TARGET_POS → CTRL.target_init → poll STATUS.done.
Use it only to change the target after boot. Hardware crops 64×64 around
TARGET_POS, builds the decimated zero-mean NCC template, and pre-trains KCF.

**Runtime (per frame):** upload → CTRL.start → poll STATUS.done → read
ABS_ROW/ABS_COL/CONFIDENCE/STATUS.

- **Acquisition (tracking=0):** sliding-window NCC over the decimated frame
  (65×45 positions ≈ 15 ms). NCC² ≥ THRESH → **immediate** KCF run on the
  64×64 crop at the found centre in the *same frame* (algo=KCF, tracking=1).
  Otherwise the NCC result is reported (algo=NCC).
- **Lock (tracking=1):** KCF crops at the last-known centre (≈ 4.2 ms incl.
  per-frame adaptation), centre += measured displacement (±31 px/frame max
  — keep the frame interval short enough that the target stays inside the
  64×64 crop).
- **Loss fallback:** KCF peak < KCF_THRESH for 3 consecutive frames →
  tracking=0, next frame re-acquires with NCC. On loss-counted frames the
  filter adaptation is **skipped** (prevents training onto the background);
  those frames finish faster (~2.3 ms).

## 5. Operational flow (software reference)

```c
#define IP_BASE 0x00042000UL
#define REG(o)  (*(volatile uint32_t *)(IP_BASE + (o)))

/* ── A. One-time init + wait for the BAKED-IN designation ───────── */
while (!(REG(0x10) & 0x2)) ;          /* boot auto-designation done    */
                                      /* (~5 ms after reset)           */
REG(0x04) = 0;                        /* MODE = AUTO                   */
REG(0x08) = 0x0040;                   /* THRESH = 0.25 (NCC² scale)    */
REG(0x0C) = 0x0001;                   /* LAMBDA                        */
REG(0x34) = 0x0080;                   /* KCF_THRESH (0 = no fallback)  */
REG(0x20) = 0;                        /* poll mode                     */
/* No designation upload — the target is preloaded (v3.1). To RE-designate
   at runtime: stream a frame, write TARGET_POS, pulse CTRL.target_init,
   poll STATUS.done. */

/* ── B. Tracking loop ───────────────────────────────────────────── */
for (;;) {
    REG(0x30) = 0;
    for (j = 0; j < 38400; j++) REG(0x28) = ((uint32_t*)cam)[j];
    REG(0x00) = 0x1;                  /* start                         */
    while (!(REG(0x10) & 0x2)) ;      /* poll done                     */

    uint32_t res = REG(0x38);         /* one read → full result        */
    int found    = (res >> 31) & 1;
    int tracking = (res >> 30) & 1;
    int algo     = (res >> 28) & 3;   /* 0 = NCC, 1 = KCF              */
    int row      = (res >> 16) & 0x1FF;   /* absolute 0..239           */
    int col      =  res        & 0x1FF;   /* absolute 0..319           */
    /* CONFIDENCE (0x1C) still available for detail if wanted */
}
```

## 6. Latency budget (50 MHz)

| Operation | Cycles | Time |
|---|---|---|
| KCF self-init + boot designation (once after reset) | ~260 k | ~5 ms |
| Acquisition frame — NCC stride 2 (+ KCF if acquired) | ~0.20 M (+0.21 M) | ~4 ms (+4 ms) |
| Tracking frame (KCF detect + adapt) | ~208 k | 4.2 ms |
| Loss-counted frame (adaptation skipped) | ~118 k | 2.4 ms |
| Frame upload | 38,400 writes | software/bus-bound (the real bottleneck) |

The NCC search stride (default 2) quarters the acquisition scan from ~16 ms to
~4 ms; the coarse ≤ 4 px error is refined by the KCF crop. The per-frame
budget is dominated by the 38,400 AXI stores (the SPI camera→SoC transfer),
not by detection.

## 7. Resource note (fits the Arty A7-100T with margin)

Two rounds of fixes brought the IP well under budget:
- **v3**: removed the `ifft2d_64` staging buffer that failed BRAM inference
  (~131 k FFs + ~35 k LUTs of muxes), `(* ram_style = "block" *)` on every
  large array, FFT results read through a port.
- **v3.1**: the forward FFT and IFFT (temporally disjoint) now **share one
  `fft2d_64` engine**, roughly halving the KCF footprint.

Standalone Vivado 2024.2 OOC synthesis of `image_ip_axilite`
(xc7a100tcsg324-1): **8,840 LUTs (14 %) / 6,624 FFs (5 %) / 59 BRAM36 (44 %) /
24 DSP / 0 latches / no "dissolved into registers" warnings**. Combined with
the trimmed `rv32imac-uart1-spi1-i2c0` Shakti build the whole design places
with comfortable margin (was 105 % LUTs before these fixes).

## 8. Obligations split

**IP team**: everything in §2–§4, §7, verified by the AXI4-Lite-only
testbench `tb_image_ip_axilite.sv` (camera-order RGB565 upload, designation,
acquisition→lock, tracked motion, loss fallback, protocol rules) plus
`tb_upload_check.sv` (bit-exact storage + decimation vs a reference model).

**Shakti side** (`gc2025`): instantiate `image_ip_axilite` on the slave-5
`kcf_master_*` wires (`clk = core_clk`, `rst_n = ~soc_reset`, `irq_out`
unconnected); add the RTL from `gc2025/hw/ip_verilog/kcf/` + the three
`.mem` files as Vivado design sources; GCSDK driver + app per §5 (update the
`KCF_FRAME_*` macros: 320×240, 2 px/write, 76,800 complete).
